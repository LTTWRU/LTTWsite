# Церковь «Свет миру» — сайт

Сайт-визитка церкви христиан веры евангельской «Свет миру», Новосибирск,
левый берег. Статический, без зависимостей, собирается одной командой.

**Концепция — «Свет из темноты».** Логотип церкви это лампа, внутри которой
планета. Сайт разворачивает эту метафору буквально: первый экран тёмный, а
свет следует за курсором и проявляет заголовок. Дальше по скроллу страница
«включается» и переходит в фирменный кремовый. Всё остальное — строгая
издательская типографика по брендбуку, без декоративного шума.

---

## Запуск

Нужен только Node 18+. Никаких `npm install`.

```bash
node build.mjs           # собрать в dist/
node build.mjs --serve   # собрать, поднять localhost:4321 и следить за файлами
```

## Что где лежит

```

src/
  layout.html            общий каркас: <head>, мета-теги, schema.org
  partials/
    header.html          шапка + мобильное меню
    footer.html          подвал
  pages/                 по файлу на страницу; первый комментарий — мета-данные
    index.html           главная
    new.html             «Я впервые» — самая важная страница для гостей
    about.html           о церкви, вера, пастор, реквизиты
    ministries.html      служения и группы
    media.html           проповеди и соцсети
    contacts.html        контакты, форма связи, пожертвования

public/                  копируется в dist/ как есть
  assets/css/style.css   дизайн-система целиком
  assets/js/main.js      всё поведение
  assets/img/            логотипы, вынутые из PDF брендбука
  assets/fonts/          Jost + место для Federov2 (см. там README)

dist/                    результат сборки, в git не хранится
```

## Как отредактировать самое частое

**Адрес, телефон, время служений, соцсети** — только `site.config.json`.
Значения подставляются во все страницы, в подвал, в мобильное меню, в
schema.org-разметку и в обратный отсчёт. Больше нигде их менять не нужно.

**Расписание.** Массив `services`:

| Поле    | Что это                                                       |
| ------- | ------------------------------------------------------------- |
| `days`  | дни недели, `0` = воскресенье, `6` = суббота; можно несколько  |
| `time`  | начало, «ЧЧ:ММ»                                               |
| `till`  | окончание; можно не указывать                                 |
| `title` | название встречи                                              |
| `note`  | абзац под названием                                           |

Одна запись может идти в несколько дней: у молитвы стоит `"days": [2, 4]`, и
в расписании она показывается одной строкой «Вт · Чт».

Из этого массива строится сразу всё: список на главной, строка «Служения» в
контактах, время в подвале и в мобильном меню, обратный отсчёт. Отсчёт сам
находит ближайшую встречу и показывает «Идёт сейчас», пока она идёт —
длительность берётся из `till`, а если его нет, считается 90 минут. Время
всегда новосибирское (UTC+7), а не то, что стоит у посетителя: человек из
Москвы увидит расписание церкви, а не пересчитанное под себя.

**Соцсети.** Блок `social` — просто адреса. Пустая строка означает, что
площадки нет, и она нигде не появится: ни иконкой в подвале, ни карточкой на
`media.html`. Появился канал — впишите адрес, и оба блока соберутся сами.
Названия, описания и иконки площадок лежат в `build.mjs` (константа `SOCIAL`)
— это оформление, а не контент, поэтому в конфиг оно не вынесено.

**Новая страница.** Положите файл в `src/pages/`, начните его с блока
мета-данных, дальше — обычный HTML. Шапка, подвал и `<head>` подставятся сами.

```html
<!--{ "title": "Заголовок вкладки", "description": "Для поиска и соцсетей" }-->

<section class="section">…</section>
```

Чтобы пункт меню подсветился на своей странице, у ссылки в
`src/partials/header.html` должен быть `data-nav="имя-файла-без-html"` —
`aria-current` проставит сборщик.

## Дизайн-система

Всё живёт в CSS-переменных в начале `style.css`.

| Токен      | Значение  | Откуда                        |
| ---------- | --------- | ----------------------------- |
| `--brand`  | `#DC5213` | брендбук, RAL 2004            |
| `--cream`  | `#F8F2DC` | брендбук, RAL 9001            |
| `--ink`    | `#1B1206` | производный тёплый чёрный     |
| `--void`   | `#0E0803` | фон тёмных блоков             |

Фирменные цвета менять нельзя — брендбук это запрещает прямо. Остальные
оттенки производные и нужны только для интерфейса.

Секцию можно перекрасить одним классом: `.on-dark` (тёмная) или `.on-brand`
(оранжевая). Оба класса переопределяют весь набор токенов, поэтому кнопки,
линии и текст внутри автоматически становятся контрастными.

### Шрифты

- **Jost** — тексты. Лежит локально, три юникод-сабсета, ~54 КБ.
- **Federov2** — заголовки по брендбуку. Гарнитура несвободная, файла в
  репозитории нет; пока его не положат в `public/assets/fonts/`, заголовки
  идут на Jost. Инструкция — в `public/assets/fonts/README.md`.

## Доступность и производительность

- Ноль зависимостей. По умолчанию — ноль внешних запросов: шрифты лежат
  локально, CDN нет. Наружу сайт обращается только в двух случаях: человек
  сам нажал «Показать карту» или в конфиг вписан счётчик Метрики.
- Без JS сайт полностью читается и работает — анимации и обратный отсчёт это
  прогрессивное улучшение.
- `prefers-reduced-motion` отключает все движения, включая бегущую строку и
  свет за курсором.
- Контраст выверен по замерам, а не на глаз: 25 проверок по всем страницам.
  Мелкий акцентный текст использует отдельный токен `--accent-text` —
  фирменный оранжевый по кремовому даёт лишь 3.6:1 и мелкому кеглю не годится.
- Клавиатурная навигация, `aria-expanded` на аккордеоне и меню, skip-link,
  `inert` на закрытом меню.

## Что осталось подставить

Это места, где нужен реальный контент от церкви:

- [ ] вычитать тексты внутри карточек на `ministries.html` — состав служений
      подтверждён церковью, но описания написаны без брифа и могут расходиться
      с тем, как всё устроено на самом деле;
- [ ] уточнить координаты в `address.lat` / `address.lon` — сейчас там центр
      Горского жилмассива, влияет только на schema.org для поисковиков;
- [ ] адреса Telegram и YouTube в `social` — сейчас пустые, поэтому эти
      площадки нигде не показываются (см. «Соцсети» ниже);
- [ ] почта: в конфиге стоит `hello@svetmiru.church`;
- [ ] видео последнего служения на `media.html` — в файле есть комментарий с
      готовым куском разметки для вставки `<iframe>`;
- [ ] фотографии церкви и пастора: сейчас вместо них графические блоки на
      фирменном оранжевом;
- [ ] реальный домен в `site.config.json` → `url` (влияет на canonical,
      sitemap и og:image);
- [ ] номер счётчика Яндекс.Метрики в `metrikaId`, если нужна статистика;
- [ ] проверить, что виджет карты отрисовался на живом сайте — из среды
      разработки его отрисовку проверить нельзя.

## Публикация

Сайт полностью статический — ему не нужен ни PHP, ни база данных, ни Node на
сервере. Подойдёт самый дешёвый тариф любого хостинга.

**Порядок такой:**

1. Впишите настоящий домен в `site.config.json` → `url` (без слэша в конце).
   От него зависят canonical-ссылки, `sitemap.xml` и картинка-превью в
   мессенджерах, поэтому сделать это нужно **до** сборки.
2. Соберите: `node build.mjs`
3. Загрузите **содержимое** папки `dist/` (а не саму папку) в корневой каталог
   сайта на хостинге — обычно он называется `public_html` или `www`.

Архив для загрузки через панель управления делается так:

```bash
node build.mjs && cd dist && zip -r ../svetmiru.zip . && cd ..
```

Настройте на хостинге страницу ошибки 404 на файл `404.html` — она уже
собрана и оформлена.

**Обновление сайта** — та же последовательность: поправили конфиг или текст,
пересобрали, залили заново. Ничего запоминать не нужно.

В репозитории лежит и `.github/workflows/deploy.yml` — он публикует сборку на
GitHub Pages при пуше в `main`. Пригодится как бесплатная тестовая площадка,
чтобы показать сайт своим до покупки домена.

## Карта

Блок «Как добраться» показывает фирменную плашку с адресом и кнопку
«Показать карту». Виджет Яндекса грузится **только после нажатия** — до этого
сайт не делает ни одного обращения наружу. Адрес виджета собирается из
координат `address.lat` / `address.lon`, отдельный ключ не нужен.

## Аналитика

`metrikaId` в конфиге пустой — счётчик не подключается. Заведите счётчик на
metrika.yandex.ru, впишите его номер, пересоберите — код появится сам. Пока
поле пустое, у сайта ноль внешних запросов.
